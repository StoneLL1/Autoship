# Implementation plan

Read the confirmed product, relevant design/flows and technical choices. Write a short plan ordered by useful, verifiable increments. Start with a narrow path through the real system that exercises the main integration or uncertainty; expand only once that path is credible. Include necessary prerequisites and integration acceptance.

Match the plan's size to the work. Simple work may need only one or two implementation tasks; split further when difficulty, uncertainty or independently verifiable outcomes justify it. Choose which tasks can share an implementation session based on related context and capacity.

Explain the sequence and important tradeoffs. For coupled changes, name the producer, consumer and agreed interface or data contract so separate tasks can join correctly. Leave routine code structure and implementation choices to the implementing agent.

Ready when every confirmed outcome maps to a planned increment and check, dependencies have a usable order, and the main user flow has end-to-end acceptance. For a new project, return to [the planning route](plan-new.md) to hand off to the task-spec session. Other routes continue to [task specs](split-tasks.md).
