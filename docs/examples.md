# 使用示例与预期行为

以下均为模拟示例，用来说明怎样写输入、怎样识别正确执行，不是已完成的产品或真实宿主接力记录。可复制示例提示词，替换目录与需求后用于自己的项目。

## 小型新项目

```text
用 autoship 在 <绝对路径> 做一个本地 Markdown 阅读器。
支持打开文件、显示正文、记住当前文件的阅读位置；不做账号和云同步。
界面简洁，键盘可操作，错误时保留已打开的内容。
请沿需求分支多轮问清需要我决定的问题，最后让我选择设计风格；其余连续推进到本地可用。
允许在宿主规则内为每份规划文档创建并启动独立 session，规划审核通过后再新建开发 session。
不必逐次问继续；能力不足时说明原因并提供人工接力。
```

预期：先查现有内容和宿主能力，按依赖多轮追问，例如文件变化时如何处理、阅读位置按什么范围保留、打开失败后保留什么。每轮保存回答和决定；已有明确答案直接采用，出口以需求分支覆盖为准。需求访谈完成后，两个子代理分别研究同类阅读器的产品行为，以及可复用的解析／渲染方案和开源实现；主 Agent 整理建议，有新增产品取舍才继续追问。最后提供具体设计方向由用户选择，保留选择理由。

将完整问答、确认与修正、排除项、两份调研及设计选择保存为可访问的上下文包，再依次以独立 session 完成 PRD、设计、用户流程、技术方案、项目约定、实施计划和任务清单，记录各自产物、出口与真实会话 ID。PRD 对照原始决定检查覆盖；开发任务可只有一两个。规划包整体审核一次，由当前规划执行者修复并验证发现，再创建开发 session。首个增量跑通打开文件到实际渲染，下一步再扩展阅读位置与边界行为；每个任务独立审核一次，主 Agent 修复并检查。

交付应包含实际启动方法、可访问结果、已检查的主流程与错误路径，以及尚缺的条件。只做了编译或生成截图，不能据此声称阅读位置恢复已通过。

## 已有项目追加搜索

```text
用 autoship 给历史记录页加搜索。匹配标题，不区分英文大小写，支持中文；
清空搜索恢复全部记录，无匹配时显示空结果。保留当前排序和删除能力。
沿用现有设计和依赖，自动完成实现、验证与本地交付。
```

预期调查：从历史页入口找到列表的数据来源、过滤位置、删除交互和既有测试。先比较可复用的搜索控件；只有本地材料不足以解决技术问题时再做外部研究。

可放在现有计划中的任务片段：

```markdown
## T01: 搜索历史记录
范围：只按标题过滤，保留原排序和删除行为。
上下文：填写实际页面、数据模块和测试路径，并说明每处用途。
A1：给定 Alpha、ALPINE、中文笔记，输入 alp，只显示前两条且顺序不变。
A2：输入 中文，只显示中文笔记；输入不存在的标题，出现空结果。
A3：清空输入恢复全部记录；删除匹配项后，清空输入也不会恢复已删除项。
检查：填写已发现的测试命令；在运行页面依次执行 A1–A3，记录结果。
```

准备实施时应将上述“填写”内容换成真实路径和命令。若自动测试通过但浏览器无法启动，A1–A3 的真实界面检查仍是待验，不能用模拟交互充当成功。

## 修复缺陷

```text
用 autoship 修复历史记录清空搜索后排序变化的问题。
预期恢复原有时间倒序，其他行为保持现状。先查原因再修复并验证。
```

预期：记录原始输入、版本、顺序变化的复现证据，定位原因；任务验收覆盖搜索、清空和排序。新缺陷走 fix 规划路径；如果这就是正在实施的 T01 的失败检查，回到原任务的 repair，继承其审核与预算。已真正交付后的新回归才建立关联修复任务。

## 中断后接力

```text
用 autoship 继续 <外部交接记录绝对路径> 中的工作。
先核对实际文件、活跃写入者、审核记录和已消耗预算，再执行记录中的下一步。
```

假设记录显示“审核已派出，创建后继的调用超时”：下一步是查原调用与接手记录，不能同时重派审核或再建执行者。若状态仍不明，保持受影响工作只读，处理独立工作或报告最小恢复条件。

若宿主没有新会话工具、只有子代理或缺少创建授权，入口即明确报告限制。在下一个规定边界按 [sessions](../skills/autoship/references/sessions.md) 保存不可变快照、登记等待接手、释放写入权并输出已填好的接力提示词。例如澄清已完成而 PRD 会话无法创建，就留下“编写 PRD”的人工接力，而不是在原会话写完全部规划与代码。提示词需包含实际工作目录、Skill/阶段文件、快照和活动记录的绝对路径、交接引用及下一动作。人工创建的后继仍须确认接手，继续下一份文档时再次遵循相同边界。

## 怎样读交付结果

| 报告内容 | 能说明什么 |
| --- | --- |
| 某版本执行具体命令、退出成功，并有对应断言或操作结果 | 该版本在所列环境下通过了对应检查。 |
| 独立审核的原始发现及主 Agent 的逐项处置、修复验证 | 审核已完成且发现有去向；仍需核对最终验收。 |
| “实现完了，应该能用” | 只有声明，缺少验证证据。 |
| “可用增量，浏览器检查待验；恢复浏览器后执行 A1–A3” | 已区分成果与未完成项，可明确接手。 |
| “新会话创建成功” | 创建请求有结果，尚不能证明已启动、接手或完成。 |
