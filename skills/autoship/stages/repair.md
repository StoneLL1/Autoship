# Repair and verify

Read the task spec, existing review findings, failed checks and consumed budget in the handoff. Use the round definitions and limits in [recovery](recover.md). Record the round before working; an interrupted round continues rather than starting over.

Fix valid problems and verify affected behavior. Use earlier failure evidence rather than repeating an unsuccessful approach. Report remaining actual defects separately from missing verification conditions. Preserve confirmed scope and synchronize changed decisions.

Keep the task's existing review and its inspected version; fixes are verified by the implementing agent without another independent review. Record the repaired version, checks and remaining budget, then return to [implementation](implement.md) for acceptance or [recovery](recover.md) if still blocked.
