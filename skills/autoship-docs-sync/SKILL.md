---
name: autoship-docs-sync
description: Use when an Autoship decision, implementation, repair or verification result changes project documentation, or when a verified lesson should update existing project guidance.
---

Read confirmed decisions, relevant diff, verification evidence and the current handoff. Locate affected authoritative documents using the project's existing index and [task context](../autoship/references/context.md). Keep this operation within the coordinating writer's ownership; an independent reviewer returns suggestions instead of editing documents.

Update only what changed: requirements, design, app_flow, technical choices, task plans or progress. Reuse existing structure and references. Distinguish planned, implemented, verified and pending work; rolled-back decisions remain failure evidence rather than current behavior.

Check related references, task IDs and contradictory statements. Return changed document paths and remaining inconsistencies, or report that no update was needed.

Keep a complete list of conditions that remain unverified, with their reasons and next checks, using [acceptance and evidence](../autoship/references/quality.md). Remove a prior item only when evidence shows it has been resolved; do not carry forward a reviewer's inability to rerun a check that the implementer already verified. Preserve the distinction between the version reviewed and the final version verified.

When a verified fix exposes a reusable project rule, update the existing convention or verification entry point with the evidence and reason. Keep failed experiments and raw logs in the external execution record. Remove or replace obsolete guidance; avoid turning every one-off observation into another permanent instruction. Keep private paths and credentials out of shared documents.

Reflect established results without rewriting execution history: retain task identities, consumed budgets, dispatched reviews and their evidence. The coordinating agent updates these facts after checking actual tools and files; document synchronization must not reset them or invent completion. Keep this operation to documents, preserve confirmed scope and do not initiate another code review. This skill can run within the current session.
