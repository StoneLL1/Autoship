# Feature

Read the current code, requirements, design, project rules and pending verification. Identify changed behavior, compatibility constraints and regression scope.

Update affected product, design and flow documents using [specify](specify.md). Revisit [technical choices](choose-stack.md) and [project conventions](init-project.md) only where the change requires it. Write the [implementation plan](plan-implementation.md) and [tasks](split-tasks.md). The runner dispatches [one planning review](review-plan.md) afterward; do not dispatch it yourself.

Reuse existing decisions and document structures. Keep planned behavior distinct from what has been implemented and verified.
