# Feature

Read the current requirements, design, project rules and pending verification. Use [investigation](investigate.md) to trace the affected behavior, consumers and existing checks. Clarify only unresolved choices with [clarify](clarify.md).

Describe the behavior delta: what is added, changed or removed, what remains compatible, and how existing users or data are affected. Use [specify](specify.md) to update only affected product, design and flow material, marking the change as proposed until implementation establishes it. Revisit [technical choices](choose-stack.md) and [project conventions](init-project.md) only where needed.

Write the [implementation plan](plan-implementation.md) and [tasks](split-tasks.md), including regression and integration acceptance. Use [planning review](review-plan.md) for one independent review of the complete package, then resolve findings with [plan repair](plan-repair.md).

Ready when the reviewed change is covered by executable tasks and its affected contracts and checks are identified. Continue to [implementation](implement.md). Reuse the project's document structure and task system throughout.
