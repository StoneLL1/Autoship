# New project

Cover these responsibilities, combining them in the same session where useful. Choose session boundaries according to the work and context, and leave relevant documents when handing off:

1. [Investigation](investigate.md), reusing findings already gathered during clarification
2. [Product, design and flow](specify.md)
3. [Technical choices](choose-stack.md)
4. [Project conventions](init-project.md)
5. [Implementation plan](plan-implementation.md)
6. [Executable tasks](split-tasks.md)
7. Dispatch [one planning review](review-plan.md) of the complete package, then resolve valid findings using [plan repair](plan-repair.md).

Use the project's filenames where established. For small work, one plan can hold the brief, technical choices and tasks; frontend design and flow remain explicitly documented. A document is ready when it explains its decisions and the next stage can use it. Once the whole package is ready and review findings are resolved, continue to [implementation](implement.md).
