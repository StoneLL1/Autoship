# Clarify

Interview the user until the goal, scope, important interactions and acceptance expectations are clear. Ask questions whose prerequisites are settled, with a recommendation; investigate facts yourself.

Research comparable products for useful features and experience, and implementation approaches for feasibility. Feed findings back into questions. Use read-only subagents when available and authorized; otherwise investigate directly.

For a frontend, ask whether the user has a design.md, preferred style or visual reference, unless already answered. Use it if supplied. Otherwise randomly choose an available design document from https://github.com/VoltAgent/awesome-design-md, record its source and revision, and keep that choice across sessions. Existing projects retain their design unless a change is requested. If the source cannot be reached, use an existing cached reference or record the missing design decision and continue independent work; do not invent a selection.

Write the agreed brief and, for a frontend, a design.md draft. Distinguish confirmed decisions, suggestions and open questions. Adopt an explicit user request or previous confirmation when it already settles the scope. Resolve remaining scope questions before implementation; subsequent routine stages do not need another approval.
