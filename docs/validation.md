## 文件与分发

贡献者可以在临时目录复现以下检查；将校验辅助脚本和原始输出留在仓库之外：

1. 枚举 Git 跟踪及未忽略的公开 Markdown，验证两个入口的 YAML frontmatter、名称、用途与代码围栏闭合。
2. 检查所有非代码块内的本地 Markdown 链接与标题锚点。区分示例占位符和真实引用，禁止分发包引用仓库 docs 或机器私有路径。
3. 将整个 skills/ 复制到隔离目录，逐文件比较哈希；只以复制后的两个入口为根遍历全部引用，确认阶段、reference、asset 和兄弟 Skill 可达。
4. 在隔离夹具中移走兄弟 Skill、添加无效锚点，确认检查能失败；恢复后再检查。失败夹具不能污染分发源目录。
5. 执行 installation.md 中的复制示例，不在测试包装中增加错误策略。检查成功复制、拒绝覆盖现有安装、源目录缺失、真实复制错误终止和保留部分安装后恢复五个分支。
6. 运行 git diff --check；保存版本、文件范围、命令与实际结果。另按变更选取下表情境做行为走查。

## 情境走查

每次记录情境 ID、输入状态、读到的文件、实际选择的下一动作、保留的限制及发现。静态推导标记“模拟”；真正运行工具的行为另附原始证据。下面是判据，不要求为每个情境新开一个 Agent 或任务。

| ID | 情境 | 可观察的预期结果 |
| --- | --- | --- |
| V01 | 已确认的小型新项目 | 采用已有确认，合并必要材料，少量任务连续推进；不会再次逐阶段审批。 |
| V02 | 给已有页面增加功能，代码中已有同类组件 | 先定位当前行为和复用模式，说明变化及兼容要求，再补受影响文档与验收。 |
| V03 | 新缺陷报告 / 当前任务检查失败 | 前者走 fix 调查与计划；后者走原任务 repair，继承审核及预算。 |
| V04 | 无视觉参考且网络不可达 | 沿用已有设计；新项目可记录明确的自拟方向，重要产品选择待确认，不能假称读到参考。 |
| V05 | 搜索摘要很好，但正文不可读 | 记录资料缺口，不以摘要证明技术事实；继续本地调查或使用已核对的替代来源。 |
| V06 | 只读 reviewer 从 autoship 入口进入 | 直接路由到 review，检查完整差异与任务上下文，不取得写入权、不更新交接、不再派 reviewer。 |
| V07 | 现有项目有暂存/未暂存修改及未跟踪二进制文件 | 保存完整脏基线所需材料；保存不全时关闭自动回退，保留用户工作区。 |
| V08 | 当前上下文过重，宿主能创建执行会话 | 保存不可变快照，登记等待接手并停止共享写入，再创建、启动与查询；后继先确认接手。 |
| V09 | 只有子代理或完全没有创建工具 | 区分 reviewer、委派和可见聊天；先在当前会话工作，确需人工交接时仍执行快照与释放写入步骤。 |
| V10 | 创建或审核调用超时，但可能已开始 | 查询原调用及接手记录，保持受影响工作只读；未知状态不触发重复派发。 |
| V11 | 已审核任务发生修复、换会话或 Skill 升级 | 保留审核发现、版本及消耗历史；主 Agent 验证改后结果，不重新派 review。 |
| V12 | 修复轮次或实现会话预算用尽 | 保存失败证据；仅在可核实的自建隔离树内考虑受限回退；预算不重置，继续独立任务。 |
| V13 | 主 Agent 已验证，reviewer 自己无法复跑 | 沿用有效的已有证据；不凭 reviewer 工具不足新增待验，也不把真实未验项删掉。 |
| V14 | 构建已启动 / 输出截断 / 日志文件已生成 | 等待并读取完成结果；未得到终态及对应结果前，检查仍未通过。 |
| V15 | 测试通过后修改了相关文件或提交 hook 改文件 | 按变更重新检查受影响行为；记录审核版本与最终验证版本，未受影响证据保留原版本。 |
| V16 | 缺独立审核能力或 UI 检查环境 | 明确待审核/待验条件，区分缺陷；只能报告相应可用增量，不能宣称完整交付。 |
| V17 | 已交付任务随后出现回归 | 基于当前成果建立关联修复，不返回旧任务基线，不撤销后续已接受成果。 |
| V18 | 宿主退出、旧写入者状态不明或记录缺失 | 先核对文件、Git、会话和执行记录；不能确认旧写入者停止时先解决所有权，未知历史不能归零。 |
| V19 | 两个任务分别通过单测，但共享接口不一致 | 对照任务契约和集成验收，修复衔接；整体交付不能由单任务通过直接推出。 |
| V20 | 修复产生一次性经验，旧规范又与代码冲突 | 调查决定与实际状态，只把可复用且有证据的知识写回原规范，替换过期内容，原始失败保留在外部。 |

## 真实宿主验证

使用隔离的小项目和现有登录，在符合宿主权限的前提下验证一条完整路径：确认需求 → 规划审核 → 实现 → 保存交接 → 真正启动后继 → 接手并继续 → 任务唯一一轮独立审核 → 修复验证 → 本地交付。按实际需要选择换会话的位置，不为测试强制拆出多余产品任务。

保存宿主名称与版本、实际调用工具、会话 ID、交接路径、接手确认、最终文件或提交和检查结果。验证后继在原会话结束后是否继续存活；如依赖原会话保持活跃，明确这一限制。审核、预算和原工作区保护的结论须有对应证据。

完成实测后更新本页并在 progress.md 追加摘要；只清除有实际证据支持的待验项。修改提示词或升级宿主后，先判断影响范围，再复核相关结论。
