# Investigate the change

Read the request and relevant project context using [context](../references/context.md). Investigate facts yourself; reserve user questions for unresolved product decisions.

1. Locate the affected user journey, current behavior, nearest reusable implementation and existing checks. For a new project, identify comparable products and the uncertain technical prerequisite that most threatens feasibility.
2. For an external dependency or reference, read the relevant official documentation or source, not only a search snippet. Record the source, revision/date, applicable idea and limitation. Compare it with what the project already has. Inspect license and attribution requirements before copying material; distinguish copying code from adopting an idea.
3. Resolve consequential uncertainty with a bounded check or small experiment. Record its input, result and implication. Stop researching when the next implementation decision has adequate evidence; avoid a catalogue that does not affect the work.

Keep a short finding in the existing plan or task spec: current behavior, proposed change, material to reuse, affected boundaries and unresolved risk. Create a separate research document only when the volume warrants it. Research expands search terms, not confirmed product scope.

Ready when the relevant change path and verification method are identifiable and each material unknown is resolved, a documented safe assumption, or an explicit blocker for the dependent work. Continue to the calling route; bring only unresolved product choices to [clarification](clarify.md).
